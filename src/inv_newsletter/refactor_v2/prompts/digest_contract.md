# Digest Output Contract

本文件定义 daily digest 的**输出结构契约**——板块顺序、主题/Ticker 分层、短主题合并、表达形式触发条件、催化剂日历。所有 Stage B 板块起草调用必读此文件。

## 1. 板块顺序与板块定义

板块定义从 `filters.yaml::summarization.sectors` 单源读取，本文件不再硬编码板块列表。**板块顺序固定**：

1. AI 模型与平台
2. 宏观与市场
3. 半导体与硬件
4. 互联网与数字广告
5. 软件与SaaS
6. 网络安全
7. 其他

AI 板块始终排第一，"其他"始终排最后。中间板块按 yaml 顺序。

## 2. 板块内组织：主题归并 + 重要 Ticker 独立成段

### 2.1 主结构 = 按细分主题分组

每个细分主题用 `### 主题名` 作为三级标题（如 `### 存储超级周期 + LTA 重估`、`### 先进封装与 Foundry 三方竞争`、`### CPU TAM Re-rate`）。

**主题顺序必须按当日重要性降序**——这是 Stage A triage 阶段已经定好的顺序，Stage B 起草时**必须严格遵守**，不要重新排序。

### 2.2 主题内重要 Ticker = 四级标题

主题内信息量大、单独成段的 Ticker 用 `#### TICKER (公司名)` 四级标题，按重要性降序。**重要性判据**（满足任一即独立成段）：

- 当日财报
- guide change（上调/下调/首给）
- 单日股价 ±5%+
- 多源交叉（≥2 家卖方覆盖，或卖方+久谦双源）
- mega-cap（NVDA, AMZN, GOOGL, META, AAPL, MSFT, TSLA）

### 2.3 次要内容用 bullet 或粗体内联

同主题下信息量较小的 Ticker / 跨公司归因 / 行业级数据用 bullet 或粗体内联（如 `**AMD × Samsung**：...`），**不**起 `####` 标题。

### 2.4 简短跟踪段 = 板块尾部

每个板块最后用 `### 简短跟踪` 收纳单源、一两行、无新事件的日常 tracking（如 MCHP 涨价滞后、Soitec JPM 维持评级、Taiwan SPE 数据），用 bullet 形式。

### 2.5 短主题合并规则（硬性）

任何 `###` 子主题如果**正文 ≤3 行**或**只承载一个单源单事件**，**不允许**单独成段——必须并入：

- (a) 最相关的现有主题块（例：`Memory ETF 单日成交超 SPY+QQQ` → 合并到"存储超级周期"作为情绪指标 bullet）
- (b) 板块尾部 `### 简短跟踪` 段

一个 `###` 主题至少要承载多源 / 跨 ticker / 因果链展开才有独立存在价值。

### 2.6 Read-through 归类规则

一条信息影响哪个板块，就放在被影响的板块，不是事件源板块：

| 事件来源 | 影响对象 | 归类板块 |
|---|---|---|
| TSLA Robotaxi 实测数据 | UBER / LYFT / GOOGL Waymo | **互联网与数字广告** |
| NVDA 投资 GLW | APH bear narrative | 半导体（APH 段，不是单独 NVDA 段） |
| DRAM ETF 成交量异常 | Memory 板块情绪 | 合并到"存储超级周期"，不单独 |
| Apple-Intel 协议 → ASML/BESI 设备需求 | Foundry 设备链 | Foundry 主题内归因，不另起设备段 |
| 久谦机器人/创新药等非 TMT | — | `## 其他` 板块 |

## 3. 表达形式触发条件

以下是**触发条件**，成立时**可考虑**使用，不要为用而用。

### 3.1 跨实体对比 / 排行榜 → 可考虑表格

满足任一条件即考虑表格：

1. **多维度对比**：≥3 个实体 × 每实体 ≥2 个独立维度
2. **排行榜 / 长列表**：单一维度但 **≥6 个实体**的排序结果（领涨/落后榜、仓位变化、估值分位、评级上调/下调、做多/做空拥挤度等）
3. **并行双榜**：领涨 vs 落后、bull vs bear、上调 vs 下调 → 一张含两组的表格或两张紧邻表格

**必须改写为表格的典型反例**（严禁顿号串）：

- ❌ `领涨：INTC +174%、SNDK +146%、CRDO +126%、FLEX +122%、STX +117%、AMD +115%...；落后：CHTR -29%、EPAM -21%...`
- ✅ 改为两列并排表格 + 下方一句共性归因

**表格后必须接一句 commentary**（共性归因 / 关键原话 / 异常点提示），表格不能孤立存在。

反向条件（不要硬塞表格）：各家故事线独立、数据点不齐、需要因果展开 → 保持 bullet 或段落。

### 3.2 二元 thesis → 可考虑子分组

当一段分析的核心 thesis 是**二元对立**时（"X 没事 / Y 才是问题"、"bull case / bear case"、"structural / cyclical"、"市场担心的 / 实际真正 miss 的"），用粗体小标题分两组，让结构本身承担分析意图。普通财报展开（无二元 thesis）保持平 bullet。

## 4. 段落与 bullet 混排

- **默认 bullet** 列要点
- 一条内容需要 2-3 句铺陈逻辑链（卖方核心观点 → 数据支撑 → 估值/股价含义）时，**写成短段落**而不是硬拆成多个 bullet
- Bullet 适合并列要点，段落适合因果链
- 篇幅：整篇 digest 目标阅读时长 8-15 分钟。**信息密度优先于篇幅压缩**——邮件量大或讨论深入时，宁可写长也不要为了简短牺牲数据点和论证链条

## 5. 催化剂日历

在文末汇总"本周关注"事件（财报、会议、数据发布等，如有）。这是 Stage C 的产出，Stage B 板块起草不需要包含。

## 6. 严禁的"元层"内容

digest 正文中**不要**出现以下任何形态：

1. **关于本 digest 自身的元信息**："基于 N 封邮件整理"、"涉及 X 封研报"、"按板块/Ticker 排序"等开场白
2. **板块/全文开场总结**："今日主线"、"叙事主线"、"executive summary"、"今日关注重点"等总结性段落
3. **任何对后文内容的预告、导览、摘要**："详见下方 X 条目"、"将在 Y 段详细展开"等

digest 应**直接以板块标题（## XXX）开始**，每个板块**直接进入第一个主题或 Ticker（### XXX）**，不留过渡段落。读者要的是内容本身，不是关于内容的描述。
